# v0.1.1 から v0.2.0 への移行ガイド

このドキュメントは **runbridge v0.1.1** から **v0.2.0** へ更新するときの手順と破壊的変更の対処です。

**関連:** リリース全体の変更一覧は [CHANGELOG.md](../../CHANGELOG.md) の「[0.2.0]」セクションと併読してください。設計メモは [api.md](../../api.md) を参照してください。

## 前提

- ターゲット feature（`lambda` / `cloud_run` / `cgi`）は **従来どおり 1 つだけ** 有効にします。複数同時はコンパイルエラーです（テスト用に `allow_feature_conflicts` あり）。
- SemVer で **マイナー 0.2** は新機能追加と破壊的変更の両方を含みます。

## 最短手順

1. `Cargo.toml` の依存を更新する。

   ```toml
   runbridge = { version = "0.2.0", features = ["cloud_run"] }
   ```

   `lambda` / `cgi` に切り替える場合は `features` だけ変更します。

2. `cargo build` を実行し、下記の対応表に沿ってコンパイルエラーを解消する。

3. 必要に応じて [CHANGELOG.md](../../CHANGELOG.md) の **Added** を読み、state / CORS / `error_handler` / 固定ファイルなどを順に取り込む。

## 破壊的変更の対応表

| v0.1.1 | v0.2.0 |
|--------|--------|
| `req.query_params` | `req.query`（`QueryMap`）。複数値は `get_all` などを利用 |
| `req.headers` が `HashMap` | `HeaderMap`（大小無視・複数値）。`get("name")` で取得 |
| 正規表現パス（例: `^/items$`） | **path template**（例: `/items`, `/users/{id}`）。静的セグメントと `{param}` のみ |
| `Handler::matches` / `path_pattern` / `handle` | `Handler` は `handle` のみ。ルート情報は `handler::get` 等が生成する `Route` が保持 |
| `RunBridgeBuilder::handler(Box<dyn Handler>)` のように生 `Handler` を並べる | `handler::get("/path", f)` などが返す `Route` を `handler(...)` に渡す |
| `Middleware::pre_process` / `post_process` | `Middleware::handle(req, next)` と `next.run(req).await` |
| `RunBridge::find_handler` | `RunBridge::resolve(path, method)` と `handle_request`、または `RouteMatch` の利用 |
| Cookie を `Response` の `headers["Set-Cookie"]` のみで表現 | `response.cookies` に `Cookie` を積む（アダプタが適切に出力） |
| `body: Option<Vec<u8>>` | `body: Option<Bytes>`（`Vec<u8>` からの変換は `Bytes::from` など） |

## ルーティング

- パターンは **path template** のみです。`{id}` 形式でパスパラメータを取ります。
- マッチ後の値は `req.path_params` に入ります（従来の正規表現キャプチャとは別 API）。
- 同じパスに複数メソッドがある場合、存在しないメソッドでは **405** と **`Allow`** ヘッダーが返ります（[CHANGELOG](../../CHANGELOG.md) の Changed 参照）。
- どのルートにも当たらない場合は **404**。`RunBridge::builder().fallback(...)` でアプリ全体のフォールバックを設定できます。

## ミドルウェアの例

```rust
use async_trait::async_trait;
use runbridge::common::{Middleware, Next, Request, Response};
use runbridge::error::Error;

struct LoggingMiddleware;

#[async_trait]
impl Middleware for LoggingMiddleware {
    async fn handle(&self, req: Request, next: Next<'_>) -> Result<Response, Error> {
        log::info!("{} {}", req.method, req.path);
        next.run(req).await
    }
}
```

グローバルなミドルウェアは `RunBridge::builder().middleware(LoggingMiddleware)` のように登録します。ルーター単位・ルート単位のレイヤーは [api.md](../../api.md) の順序説明を参照してください。

## エラー応答のカスタマイズ

ハンドラ、fallback handler、ミドルウェアが `Err(Error)` を返したときの HTTP レスポンスは、`RunBridge::builder().error_handler(...)` で差し替え可能です。**404 / 405 の固定レスポンスには適用されません**（README の Error Handling 例参照）。

## 任意の新機能

以下は移行完了後に順に検討できます。

- **App state:** `.state(Arc<T>)` と `State<T>` extractor（[README](../../README.md)）
- **CORS:** `Cors` middleware と `try_validate()`
- **固定ファイル:** `fixed_file` / `fixed_file_with`（汎用 static server ではない点に注意）
